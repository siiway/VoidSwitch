# 身份组

**身份组** ("role group") 承载两种正交的能力：

- **成员资格**（membership）— 决定成员可以调用哪些[模型](/admin/models)。
- **管理员资格**（adminship）— 授予**只读观察者**视图：查看该组的用户、统计和日志。**不**授予模型调用权。

**身份组**页面对 owner / co-owner / admin 可见，但**只有 owner / co-owner 可以编辑**；平台 admin 只能查看列表和成员。

## 成员资格与管理员资格如何运作

两者都在**登录时根据用户的 Prism 团队角色自动分配**。每个组定义一个或多个**映射**，每条映射的形式为：

> 团队 `T` 中有效角色至少为 `R` 的成员，获得此组的 **`grants`** 权限。

`grants` 有两个取值：

- `member` — 成员资格（模型调用权）。
- `admin` — 管理员资格（只读观察者）。

角色排序为 `owner > co-owner > admin > member`。**管理员资格不隐含成员资格** — 若同时需要，请为同一 (team, min_role) 组合添加**两条**映射，一条 `作为 成员`、一条 `作为 管理员`。

自动分配的成员与管理员资格在每次登录时重新计算；临时移除的自动成员在下次登录时（若映射仍匹配）会被重新授予。手动分配的（`source="manual"`）不会被自动流程覆盖。

## 创建组

1. 打开**身份组** → **添加**（仅 owner / co-owner 可见）。
2. 命名并加可选描述。
3. 添加**映射**：团队 ID、最低角色、以及 `作为 成员/管理员`。
   > 编辑对话框顶部会常驻一段提示，说明管理员映射不含模型访问权。
4. 保存。然后在[模型](/admin/models)页面中，把这个组列进要解锁的模型下。

## 身份组管理员的视图

一位**身份组管理员**（不必是平台 moderator）登录后，会在导航中看到 **Users / Statistics / Logs / Audit** 四个页面，但内容**仅限其所管理的身份组的成员**：

- **Users** — 只列出这些组的成员。搜索框上方有一条 `您是 A, B 身份组的管理员，此列表仅显示这些身份组的成员` 提示；管理多个组时可通过下拉框在"全部"与单组之间切换。角色列不显示（仅"团队角色"可见），也不能修改角色 / 启用禁用。可以对**成员**执行**强制登出**（但不能对 staff 或同组的其他管理员）。
- **Statistics** — `/api/usage` 数据被按管理组的成员作用域化。同样有提示条和组选择器。
- **Logs / Audit** — 只看到本组成员产生的请求日志；审计日志只看到 `target=user`（且 user 属于本组）或 `target=role_group`（且属于本组）的条目。请求日志详情里可见 headers 与调试尝试，但**看不到 request/response body**（body 仅 owner/co-owner 可见）。所有的 `reveal` 操作依然仅 owner 可用。

::: warning
**身份组管理员是只读角色**（除强制登出外），无法编辑身份组、无法修改用户、无法查看敏感值或明文 Void-Token。
:::

## 调用限流

每个身份组都有自己的**调用限流**：其成员在 OpenAI / Anthropic 网关端点
（`/v1/chat/completions`、`/v1/messages`）上"N 秒内最多 X 个请求"。
新建的组默认 30 秒内最多 30 个请求；最大请求数设为 `0` 表示该组不限流。
限流仍**按用户计数**：一个成员加入多个身份组时，只要其中任一组（且该组有权调用
相应模型）还有额度，就可以继续调用。

在组的编辑对话框中修改限流。内置 **moderator** 组不能重命名、不能修改映射，
但可以调整它的限流（默认 30 秒内最多 50 个请求）。

::: tip
控制台管理操作（添加/编辑/删除/保存）的限流是固定的（20 秒内最多 30 个请求），
不在此处配置。
:::

## 内置 moderator 组

**moderator** 组在首次启动时创建，始终授予对所有模型的访问权限，不可重命名或删除
（但其调用限流可以调整）。Owner / co-owner / admin 隐式属于它 — 这就是为什么管理人员
始终可以调用任何模型。

内置组**不接受** `grants="admin"` 映射 —— 其管理权来自平台角色本身，无需再单独授予。

## 紧急移除访问权限

从组的**成员**视图中，owner / co-owner 可以临时移除用户，以立即切断其对该组模型的访问权限
（适用于无法立即禁用账户的情况）。如果映射仍然匹配，将在下次登录时重新授予 —
要使其永久生效，请移除映射或禁用账户。
