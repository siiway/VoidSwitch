# 节点与节点组

**节点**（Node）是网关用来连接上游供应商的出口跳点（egress hop）。旧版"代理"概念被
**节点 + 节点组**系统取代。**节点与节点组**页面是**仅限管理人员**的。

## 节点类型

每个节点有一个**类型**，决定它如何建立出口连接：

- **direct**（直连）— 走代理进程本身的网络，直接连接。
- **http** — HTTP 转发代理。
- **socks5** — SOCKS5 代理。
- **agent** — 一个 voidswitch-agent 中继，用令牌认证。

## 节点组

**节点组**（Node Group）是可自由创建的节点集合，用于决定一个请求应该走哪些出口路径。
一个组可以：

- 从全局节点池中挑选节点，并且/或者
- **继承**其他组（实时引用，类似 Python 类的继承；环引用会安全地解析）。

每个组可以设置自己的 `probe_url` 和 `probe_interval_seconds`，用于空闲时的健康检查。

### 动态排序与故障转移

组内节点按健康度/延迟排序：

- 排序依据是 **EWMA 延迟 + 失败评分**，权重可在设置（`node_rank_alpha/beta/gamma`，衰减半衰期 `node_rank_ewma_half_life_seconds`）中调整。
- 请求从前到后遍历排序后的列表，失败时自动回退到下一个。
- 所有节点都失败且重试耗尽后，返回连接错误。
- 每个请求的最大重试次数（`max_retries`）以及节点被禁用的失败阈值（`max_proxy_failures`）都是设置项。

### 固定节点（Pin）

在节点组展开的成员列表中，任意节点都可以被 **Pin**：被 Pin 的节点**始终排在列表最前**，并独立于质量评分单独排序（它们内部仍按评分排序）。这适合强制某些节点优先被使用（例如某条高质量专线），而不必调整它们的延迟/失败指标。节点组页面不再支持手动拖拽排序——排序完全由上述动态评分（加 Pin）决定。

### 空组 → 直连（防锁定）

一个**没有可用节点**的节点组的请求会**回退为直连**。无论路由配置多糟糕，都不会把你
锁在门外 —— 这是有意设计；**System 组 / 登录令牌**保护着登录。

### System 节点组

**System 组**是节点组中唯一的特殊组，承载系统请求：

- Prism OAuth、models.dev 同步、余额探测、OAuth 令牌刷新。

只有 owner / co-owner 可以编辑其节点。System 组为空时 → 直连（保证登录/OAuth 始终可用）。

### 默认节点组

没有显式指定节点组的供应商使用**默认节点组**。

## 代理切换关闭

如果在设置中禁用了**代理切换**（`proxy_switching_enabled=false`，因为外部代理如 mihomo
已经处理出口），路由系统关闭：每个请求使用单一的**静态代理 URL**（`static_proxy_url`，或
`HTTP(S)_PROXY` 环境变量，都没有时才直连）。在此模式下**不会**发生故障转移，也不会自动禁用节点。
路由关闭时，Proxies（节点）选项卡从导航中隐藏。

Claude Code 订阅 OAuth 的令牌交换和刷新遵循同一模式：静态代理 URL 有值时走该代理；为空时使用
进程环境中的 `ALL_PROXY` / `HTTPS_PROXY` / `HTTP_PROXY`，都没有时才直连。
