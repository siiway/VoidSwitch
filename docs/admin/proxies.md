# 代理

代理是网关用来连接上游供应商的可选出口路由。
**代理**页面是**仅限管理人员**的。

## 添加代理

1. 打开**代理**。
2. 粘贴一个或多个代理 URL，**每行一个**，例如
   `http://user:pass@host:port` 或 `socks5://host:port`。
3. 可选地设置**名称**（也用作描述）、**本地源 IP**（`local_address`）和**权重**。

添加后，每个代理行都可以通过**编辑**按钮随时重命名。名称仅用于在列表中辨认代理，
不影响路由。

## 代理如何使用

- 供应商的**出口代理**模式决定它使用**所有**活跃代理、仅**选定**的代理，还是**直连**。
- 在发生网络/超时错误时，调度器会故障转移到另一个代理，并在超过动态失败阈值后禁用有问题的代理
  （需**代理健康检测**开启，见下文）。
- 后台**代理健康检测**会定期重新测试已禁用的代理，并重新启用那些恢复的代理。
  其间隔可在[设置](/admin/settings)中调整。

### 代理健康检测

[设置](/admin/settings)中的**启用代理健康检测**是自动代理健康管理的总开关：

- **开启**（默认）：网关会探测已禁用的代理以重新启用恢复的代理，并在某个代理连续失败超过
  阈值时**自动禁用**它。
- **关闭**：完全不做健康探测、不自动禁用、也不自动启用 —— 把代理连通性交给外部管理
  （例如一个 mihomo 实例）。失败仍会计数，但代理不会被网关自行下线。

## 代理切换关闭

如果在设置中禁用了**代理切换**（因为外部代理如 mihomo 已经处理出口），
代理选项卡将被隐藏，每个请求使用单一的**静态代理 URL**（或直连）。
在此模式下不会发生故障转移或自动禁用。

Claude Code 订阅 OAuth 的令牌交换和刷新也遵循这个模式：静态代理 URL 有值时走该代理；为空时使用
进程环境中的 `ALL_PROXY` / `HTTPS_PROXY` / `HTTP_PROXY`，都没有时才直连。
