# 日志与用量

VoidSwitch 记录每个请求，以便你查看发生了什么以及使用了多少。

## 统计

**统计**页面显示用量分析。成员查看**自己**的流量；管理人员查看按用户、令牌、模型和供应商细分的平台范围总量，
覆盖日、周、月和年窗口。

页面自上而下包含：

- **总览** — 请求总数、成功 / 失败数、Token 用量与**成功率**。
- **性能** — **平均首字时间（TTFT）**、**平均请求时长**、**平均 Token/请求** 与 **Token 吞吐（tokens/秒）**。
  首字时间从网关发起上游请求到收到第一个**实际内容 token** 计算（流式请求；控制帧不计入），
  平均请求时长使用数据库记录的「开始时间 → 结束时间」差值。
- **请求质量** — **流式 / 非流式**请求数量，以及**状态码分布**（每个状态码的出现次数）。
- **按时间** — 请求与 Token 用量的时间序列，每个时间段还附带**平均首字时间**列。
- **按用户 / 按令牌 / 按模型 / 按供应商** — 各项的用量排行；点击条目可在请求日志中查看对应明细。

在管理人员的**按用户**细分中，用户名是可点击的：点击后会弹出该用户的**活跃度热力图**弹窗
（与控制台底部的热力图相同 —— 每日 Token 用量、累计 / 峰值、最长任务时长与连续天数）。

## 日志

**日志**页面有两个视图：

- **请求** — 每次网关调用一行：时间、用户、令牌、模型、请求 IP、状态、状态码、首字时间、
  **请求时长**、Token 数和尝试次数，以及任何错误。成员只看到自己的请求；管理人员看到所有人的。
  IPv6 地址在单元格中截断显示 `…`，将鼠标悬停可查看完整地址；ID 永不断行。
  请求时长在完成前为 `开始时间 → 现在` 的差值，**仅在实时日志流连接时**每秒动态增长（参见下方「实时日志流」），
  否则对进行中的请求显示 `—`；完成后固定为 `开始时间 → 结束时间` 的差值。
  **首字时间**仅对流式请求有意义：它测量从网关向上游发起请求到收到第一个实际内容 token 的耗时
  （忽略 `message_start` / `ping` 等控制帧），而不是第一个网络字节的时间。
- **审计** *(管理人员)* — 谁更改了什么的行政管理记录。

使用过滤器缩小结果范围，使用分页器浏览页面：

- **请求**日志按**模型**、**用户**、**令牌**（均为「搜索 + 选择」下拉框，可输入关键字过滤后选择）、
  **提供商**（直接下拉选择）、**请求 IP**（自由文本，部分匹配，支持 `*` / `?` 通配符，如 `10.0.*`）、
  **状态码**（自由文本）以及**请求状态**（进行中 / 已完成 / 已取消 /
  错误 / 已切断，下拉选择）筛选。状态码可直接填具体数字（如 `404`），
  或只填一位数字 `2` / `3` / `4` / `5` 并失焦，会自动补全为 `2xx` / `3xx` / `4xx` / `5xx`，
  匹配该类下的全部状态码。
- **审计**日志按**范围**、**操作**、**目标类型**、**操作者**（搜索 + 选择）以及 **IP** / **User-Agent**
  文本筛选。IP 与 UA 为部分匹配，并支持 `*`（匹配任意字符）与 `?`（匹配单个字符）通配符，
  例如 `10.0.*` 或 `curl/*`。
- 两个视图都支持按**时间范围**筛选：**时间**下拉框提供「全部时间 / 最近 1 小时 / 最近 24 小时 /
  最近 7 天 / 最近 30 天」等快捷区间，选择「自定义」后会展开两个日期时间输入框，可精确指定开始与结束时刻。
  选择快捷区间时会把当前时刻固定为窗口边界，翻页或刷新时区间保持稳定，不会随时间悄悄漂移。
- 直接**点击**表格中的任意值（请求的 用户 / 令牌 / 模型 / 状态 / 请求 IP，审计的 操作者 / 范围 / 操作 / 目标 /
  IP / UA）即可把它填入对应的过滤器。
- 文本类过滤器（请求的状态码，审计的 IP / User-Agent）在输入时会**防抖**，停止输入片刻后才发起查询，
  因此边输入边筛选更流畅、不会每敲一个字符就刷新一次。当任意过滤器（含时间范围）生效时，
  过滤栏右侧会出现**清除筛选**按钮，一键恢复到未筛选状态。

### 实时日志流（SSE）

请求日志支持**实时刷新**：在页面标题旁的**刷新按钮**旁边有一个连接 / 断开按钮，点击连接后，
新写入的请求日志行会通过 SSE 自动出现在表格顶部（默认先跳过当前已显示的记录，只推送更新的）。

- 实时流会应用与列表相同的**筛选条件**（模型 / 用户 / 令牌 / 提供商 / 状态码 / 请求状态），
  并遵循相同的权限边界：成员只能实时看到自己的请求。
- 实时推送以**轮询**方式驱动（每秒一次、基于 `id` 索引、无连接查询、单次最多 100 行），
  不挂钩网关热路径，因此对请求吞吐几乎没有影响。
- 每个用户可同时打开的实时日志流数量受设置 **每个用户同时连接的实时日志流上限**
  （`sse_max_connections_per_user`，默认 2，`0` = 不限制）约束；健康流也共享此额度，超出返回 `429`。
  同一用户开着多个浏览器标签页时要注意该限制。
- 断线（例如超时或网络波动）会自动停止并显示提示，可重新点击连接。

Claude Code 订阅 OAuth 的令牌交换也会计入**请求**日志。它们不是模型推理请求，模型列会显示特殊值，
例如 `<cc-refresh-token>` 或 `<cc-exchange-token>`；这类记录通常没有用户和 Void-Token。

每个请求行都有一个**信息**按钮（ℹ），打开其常规详情 —
时间、开始 / 结束时间、**请求时长**（`开始 → 结束` 的总墙钟）、**连接耗时**（与上游建立连接所花的
时间：DNS + TCP + TLS；连接池复用命中时接近 0）、首字时间、请求状态（含完整文字）、完整请求 IP、
调用者、令牌、模型、入站风格、是否流式、总尝试次数、User-Agent、插件版本和任何错误 ——
表格中的每个表头在这里都以**未截断**的形式完整展示。
与具体某次尝试相关的字段（供应商、密钥、代理 / 节点、上游模型与 URL、状态码、Token 用量、每次尝试耗时）
不再放在总览里，而是收进下方的**每次尝试**卡片，避免总览被最后一次尝试的值误导。

### 每次尝试（重试链路）

每个请求的详情都会以卡片列表展示**整条故障转移链路**：每次尝试一张卡片，默认**折叠**。
折叠时只显示序号、上游状态、供应商 · 上游模型 · 密钥预览 · 尝试耗时；点击展开后显示该次尝试的详细信息 —
状态码与错误、**连接耗时**、代理 / 节点、Token 用量、出站方法 / URL、网络调用明细。**请求头 / 响应头**以及
（owner / co-owner 查看且该请求来自调试令牌时的）请求体 / 响应体，只在管理员及以上的**调试视图**里可见。
请求头中的凭证值始终被屏蔽。

### 调试详情（管理员及以上）

每次尝试的链路与**脱敏后的请求头 / 响应头**始终记录。管理员（admin / co-owner / owner）可在任意产生过
上游尝试的请求行上用**调试**按钮（🐞）打开完整的每次尝试视图。**身份组管理员和成员看不到请求头**，
只能看到不含头/体的链路摘要。

请求体 / 响应体仅在以下情况记录，并只对 **owner / co-owner** 可见（均按**请求/响应体捕获上限**截断）：

- 该请求使用的 **vs-token 启用了调试**：记录请求体、非流式响应体，以及流式响应的上游 SSE；
- 请求**出错**（上游 4xx / 5xx）：无论是否启用调试，都会记录该次错误的响应体（通常就是上游返回的 JSON
  错误信息）；流式 SSE 不记录正文。

在调试详情弹窗左下角可以下载脱敏后的请求 JSON。导出格式把整条链路放在单个 `attempts` 数组里，
隐藏 API key、访问令牌和代理 URL；非 owner 用户导出时不会包含请求体和响应体。

这部分数据属于调试信息：超过**调试日志保留窗口**（`debug_log_retention_days`，见[设置](/admin/settings)）
后会从行上剥离请求/响应头、请求/响应体、每次尝试明细与代理地址，仅保留不含头/体的链路摘要。

## 成员可以看到什么

- 你自己的请求日志和用量。
- 不能：其他用户的流量、审计记录，以及请求头 / 请求体 / 响应体。请求头仅 **admin 及以上**可见
  （身份组管理员不可见），请求体 / 响应体仅 **owner / co-owner** 可见。

## 保留

旧日志可能会根据所有者配置的保留窗口自动清理（参见[设置](/admin/settings)）。
如果保留设置为 `0`，日志将无限期保留。

热力图所依赖的每日用量汇总**独立**于请求日志保留，按**热力图数据保留天数**
（`heatmap_retention_days`）单独清理，因此即使收紧请求日志保留，热力图仍会保留。该值默认 365 天，
可配置，但不得少于 365 天（`0` 表示永久保留）。
